# Идентификация пользователей, аутентификация и RBAC (Identity & Access Architecture)

**Статус документа:** `COMPLETED`  
**Категория:** Безопасность и Приватность (`04-security`)

---

## 1. Концепция аутентификации и идентификации

В Treeline Tracker аутентификация строится на базе **Firebase Authentication** с поддержкой сессий и пользовательских ролей через Firebase Custom Claims:

```typescript
export type UserRole = 'hiker' | 'guide' | 'rescuer' | 'admin';

export interface UserProfile {
  uid: string;                 // Уникальный идентификатор пользователя
  email: string;               // Email адрес
  displayName: string;         // Отображаемое имя ("Александр", "Кирилл")
  role: UserRole;              // Назначенная роль в системе
  activeGroupId: string | null;// ID активной группы (для туристов и гидов)
  createdAt: number;
}
```

---

## 2. Ролевая модель доступа (Role-Based Access Control / RBAC)

Система реализует четыре уровня привилегий с принудительным контролем в `firestore.rules`:

| Роль | Назначение | Права доступа в рамках системы |
| :--- | :--- | :--- |
| **`hiker`** | Обычный турист / участник | Передача собственной GPS-телеметрии, чтение маршрута и участников своей группы, отправка сообщений и SOS-сигнала в чат своей группы. Доступ к чужим группам закрыт. |
| **`guide`** | Лидер группы / Гид | Создание и управление группой, редактирование маршрута (с OCC-блокировкой), просмотр статусов и телеметрии всех участников своей группы, подтверждение прохождения чекпоинтов. |
| **`rescuer`** | Оператор спасательной службы / МЧС | Мониторинг всех активных групп в назначенном географическом секторе, обработка экстренных SOS-вызовов, запуск ИИ-алгоритмов генерации поисковых зон, координация спасработ. |
| **`admin`** | Администратор системы | Управление ролями и клеймами пользователей, просмотр журнала аудита (включая логи ИИ-решений), мониторинг системных метрик и лимитов API. |

---

## 3. Защита на уровне Firestore Security Rules

Все операции чтения и записи верифицируются на стороне базы данных:
- Запрос проверяет `request.auth != null`.
- Проверяется принадлежность `request.auth.uid` к `resource.data.memberIds` или роль `rescuer`/`admin`.
- Создание и редактирование маршрутов доступно только гиду группы (`resource.data.guideId == request.auth.uid`).
- Запись телеметрии разрешена только для собственного `userId`.
