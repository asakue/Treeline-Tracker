## 1. Концепция децентрализованной идентичности

В Treeline Tracker идентификация пользователя не привязана жестко к централизованным серверам или номерам телефонов. Каждый участник при первом запуске создает локальный криптографический профиль:

```typescript
export interface UserIdentity {
  userId: string;              // Публичный хеш (npub / hex)
  displayName: string;         // Отображаемое имя ("Алексей", "Елена")
  publicKey: string;           // Публичный ключ Ed25519 для проверки подписи
  privateKey?: string;         // Приватный ключ Ed25519 (только в Secure Storage)
  createdAt: number;
}
```

## 2. Ролевая модель группы (Access Control)

```
┌──────────────────┬────────────────────────────────────────────────────────┐
│ Роль             │ Права доступа в рамках группы                          │
├──────────────────┼────────────────────────────────────────────────────────┤
│ Group Owner      │ Управление группой, удаление, сброс группового ключа   │
│ Organizer/Leader │ Загрузка маршрута, изменение радиуса, прием SOS        │
│ Member           │ Передача и чтение локаций, чат, отправка SOS           │
│ Emergency Contact│ Доступ только к аварийной телеметрии при статусе SOS   │
└──────────────────┴────────────────────────────────────────────────────────┘
```
