## 1. Честность архитектуры: Прототип против Production

Главный принцип проекта Treeline Tracker — **полная прозрачность между тем, что реально функционирует, что эмулируется в виде симуляции, а что является концептуальным исследованием**.

Проект **не является** готовой коммерческой спасательной системой и не предназначен для использования в реальных опасных для жизни ситуациях без сертифицированного аварийного радиооборудования.

## 3. Таблица классификации компонентов

| Компонент | Текущий статус | Production эквивалент | Разрыв (Production Gap) |
|---|---|---|---|
| **GPS / Геолокация** | `SIMULATED` / `IMPLEMENTED` (HTML5 Geolocation) | Нативный GNSS-чип + RTK/Sensor Fusion | Высокая точность, фильтрация помех, фоновый режим ОС |
| **Mesh-связь** | `SIMULATED` (`MockMeshCoreTransport`) | Физический MeshCore LoRa узел (ESP32/nRF52) | BLE-драйвер, радиофизика, коллизии эфира, регулирование частот |
| **Экстренный шлюз** | `SIMULATED` (`MockEmergencyGateway`) | API центра управления кризисными ситуациями (ЦУКС МЧС / 112) | Официальные соглашения, SLA 99.999%, аудит каналов связи |
| **ИИ-поиск пропавших** | `PROTOTYPE` (Genkit Flow) | Интегрированная ГИС-модель SAR (Lost Person Behavior + Elevation DEM) | Точные цифровые модели рельефа, валидированные спасателями алгоритмы |
| **Хранение данных** | `IMPLEMENTED` (`LocalStorage` / `MockRepository`) | Защищенный бэкенд с Row-Level Security и крипто-анклавами | Синхронизация между устройствами, аудит сессий |
