# Фронтенд-архитектура Treeline Tracker (Frontend Architecture)

**Статус документа:** `COMPLETED`  
**Категория:** Архитектурная спецификация (`03-architecture`)

---

## 1. Концепция и структура слоев

Фронтенд спроектирован на базе Next.js 15 (App Router) и React 18 с ориентацией на модульность и компонентную изоляцию.

### Структурные модули:
- **`src/views/`** — композиционные экраны верхнего уровня (`MapView`, `RoutePlanner`, `LocationTracker`, `EmergencyServices`, `GroupChat`, `ProfilePage`, `WeatherForecast`).
- **`src/features/`** — интерактивные функциональные блоки со своим состоянием (`route-drawing`, `hiker-search`, `group-management`, `emergency-services`).
- **`src/entities/`** — доменные сущности с типами и репозиториями (`hiker`, `group`, `route`, `app`).
- **`src/shared/`** — переиспользуемые UI-компоненты (shadcn/ui), утилиты, хуки и конфигурация темы.

---

## 2. Картографическая подсистема (Leaflet Engine)

Карта является центральным элементом визуализации:
- Использование динамического импорта (`dynamic(() => import(...), { ssr: false })`) для предотвращения ошибок SSR с объектом `window` и Leaflet.
- Рендеринг слоев:
  - **Слой трека (Polylines):** Плановый маршрут с контрольными точками и высотным профилем.
  - **Слой участников (Markers):** Интерактивные маркеры с аватарами, направлением движения и статусом связи (LTE / Mesh / Offline).
  - **Слой геозон (Geofences):** Окружности безопасного радиуса группы.
  - **Слой поисковых секторов (Search Zones):** Полигоны вероятных областей нахождения потерявшегося туриста, рассчитанные ИИ.

## 3. Режим экспедиции и Safety Mode UI

Интерфейс адаптируется при старте экспедиции:
- **Safety Bar:** Верхняя фиксированная плашка с индикацией активного транспорта, точности GPS, статуса шифрования и заряда батареи.
- **Экстренная кнопка SOS:** Быстрый доступ с плавающей панели с защитой от случайного нажатия (Long-press 3 сек).
- **Темная тема по умолчанию:** Оптимизирована для сохранения энергии экрана в полевых условиях и комфортного чтения в сумерках.

## 4. Экран профиля и криптографической безопасности (ProfilePage)

Компонент `src/views/profile-page.tsx` является центральной точкой управления персональными данными туриста и параметрами безопасности:
- **Двухвкладочная архитектура:**
  - **Вкладка «Профиль» (`profile`):** Персональные реквизиты (имя, email, телефон, биография, аватар), сводная статистика походов и реактивный индикатор заполненности профиля (от 0% до 100%). При неполном профиле выводятся карточки-подсказки с недостающими полями.
  - **Вкладка «Безопасность» (`security`):** Управление криптографической идентичностью туриста.
- **Интеграция с IdentityManager:**
  - Извлечение локальной ключевой пары Ed25519 через `identityManager.getLocalIdentity()`.
  - Отображение публичного ключа и его компактного шестнадцатеричного отпечатка (fingerprint).
  - Безопасная ротация ключей (`rotateLocalIdentity()`) с автоматическим обновлением отображаемых реквизитов.
- **Селектор режимов приватности:**
  - Переключение режимов передачи координат: `NORMAL` (высокая точность), `REDUCED` (огрубление до 200 м), `STEALTH` (запрет передачи в эфир).
  - Персистентное сохранение выбранного режима в профиль через `routeRepository.saveUserProfile()`.
- **Карточка криптографических стандартов:**
  - Визуализация действующих протоколов нулевого разглашения: `Ed25519 WebCrypto`, `AES-256-GCM AEAD` и `Anti-Replay & Nonce`.

## 5. Тестирование фронтенд-компонентов (Vitest & RTL)

Для фронтенда развернута тестовая инфраструктура на базе **Vitest 5.0**, **React Testing Library** и **JSDOM**:
- Настройка тестовой среды: `vitest.config.ts`, подключение расширений DOM-ассершенов (`@testing-library/jest-dom/vitest`).
- Комплект тестов профиля `src/views/__tests__/profile-page.test.tsx`:
  - 16 комплексных проверок: корректность отображения данных пользователя, fallback-значений при пустых полях, открытие и валидация модального диалога редактирования.
  - Верификация точности расчета прогресса профиля: 0% (пустой профиль), 20% (только имя), 40% (+ email), 60% (+ телефон), 80% (+ биография), 100% (все поля + аватар).
  - Переключение на вкладку безопасности с эмуляцией нативных событий Radix UI (`fireEvent.mouseDown` на `TabsTrigger`).
  - Проверка ротации ключей Ed25519, копирования в буфер обмена, переключения режимов приватности и отображения протоколов шифрования.
