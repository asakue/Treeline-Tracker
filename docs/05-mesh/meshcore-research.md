## 1. Что такое MeshCore

**MeshCore** — это современная открытая архитектура и протокол ячеистой радиосвязи, разработанный для обмена сообщениями и телеметрией без использования сотовой инфраструктуры и интернета через энергоэффективные LoRa-трансиверы (на базе микроконтроллеров ESP32, nRF52 и чипов Semtech SX1262 / SX1276).

### Ключевые архитектурные свойства:
- **Децентрализация (Ad-hoc Mesh):** Каждый узел сети может выступать в роли клиента или ретранслятора (Repeater/Router).
- **Многошаговая доставка (Multi-hop Flooding / Managed Routing):** Пакеты автоматически ретранслируются соседними узлами с ограничением максимального количества прыжков (TTL / Hop Limit) для предотвращения зацикливания.
- **Низкое энергопотребление:** Использование модуляции LoRa позволяет устройствам работать неделями от компактного аккумулятора 18650.
- **BLE Companion API:** Смартфон подключается к аппаратному LoRa-модему по Bluetooth Low Energy (BLE), передавая полезную нагрузку через стандартные GATT-характеристики.

## 2. Пакетная модель и ограничения физического уровня

| Параметр LoRa | Значение для MeshCore | Влияние на архитектуру Treeline Tracker |
|---|---|---|
| **Максимальный размер полезной нагрузки (MTU)** | 237–256 байт | Пакет `EncryptedPacket` должен быть максимально компактным. |
| **Битрейт (Data Rate)** | ~1–5 кбит/с | Запрет передачи тяжелых данных (фотографий, аудио). Только телеметрия и короткие тексты. |
| **Duty Cycle (Ограничения эфира)** | 1% в полосах 868 МГц / 433 МГц | Частота отправки координат должна регулироваться (не чаще 1 раза в 10–30 секунд). |
| **Дальность связи** | 2–15 км (прямая видимость) | В каньонах и густом лесу требуется размещение промежуточных ретрансляторов на высотах. |

## 4. Что реализовано, что симулируется и путь к Production

- **Реализовано в прототипе:** Пакетный формат, совместимый с ограничениями MTU, криптографическая упаковка и интерфейс `ITransport`.
- **Симулируется:** Программный класс `MockMeshCoreTransport`, эмулирующий топологию узлов (Node A, Node B, Node C, Node D), задержку радиоэфира и вероятность потерь пакетов.
- **Production Migration (Что потребуется для реального железа):**
  1. Реализация BLE GATT драйвера через Web Bluetooth API или нативный плагин Capacitor/React Native.
  2. Сериализация в компактный бинарный формат (Protocol Buffers / CBOR) вместо JSON.
  3. Соответствие региональным частотным сеткам (868 МГц в РФ/ЕС, 915 МГц в США).
