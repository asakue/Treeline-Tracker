## 1. Определение готовности задачи (Definition of Done — DoD)

Любая функциональная или архитектурная задача считается полностью завершенной (`DONE`), только если выполнены следующие 8 обязательных этапов:

```
┌──────────────┐     ┌──────────────┐     ┌────────────────┐     ┌──────────────┐
│ Требование   │ ──> │ Архитектура  │ ──> │ Реализация     │ ──> │ Unit / Sec   │
│ & Контракт   │     │ & Дизайн     │     │ & Типизация    │     │ Тесты        │
└──────────────┘     └──────────────┘     └────────────────┘     └──────────────┘
       │                                                                │
       ▼                                                                ▼
┌──────────────┐     ┌──────────────┐     ┌────────────────┐     ┌──────────────┐
│ Статус в     │ <── │ Production   │ <── │ Русскоязычная  │ <── │ Симуляция &  │
│ Матрице      │     │ Gap Анализ   │     │ Документация   │     │ Демо-сценарий│
└──────────────┘     └──────────────┘     └────────────────┘     └──────────────┘
```

1. **Requirements:** Зафиксировано требование с идентификатором (`FR-xxx` / `NFR-xxx`).
2. **Architecture:** Разработан интерфейс в доменном слое без привязки к конкретным библиотекам.
3. **Implementation:** Написан строго типизированный код на TypeScript (`strict: true`) без `any`.
4. **Testing:** Покрыто модульными тестами, включая позитивные и негативные сценарии (атаки, отказы, граничные значения).
5. **Simulation & Demo:** Интегрировано в воспроизводимый демонстрационный сценарий симулятора.
6. **Documentation:** Обновлены русскоязычные документы в `docs/` и диаграммы.
7. **Production Gap:** Задокументирован разрыв между симуляцией и промышленным оборудованием.
8. **Traceability:** Проставлен актуальный статус в матрице прослеживаемости.

## 2. Критерии приемки ключевых сценариев

### Сценарий AC-01: Сквозное шифрование пакета локации (E2EE AEAD)
- [x] Пакет `LocationUpdate` формируется с координатами, временем, зарядом и `sequence`.
- [x] Шифрование выполняется алгоритмом AES-256-GCM AEAD; тело пакета передается в base64 байтовом виде.
- [x] При модификации хотя бы одного байта шифротекста получатель выбрасывает `AuthenticationError` и не отображает точку на карте.
- [x] При отправке пакета с ранее использованным `packetId` или устаревшим `timestamp` (> 10 мин) пакет отвергается модулем `ReplayProtection`.

### Сценарий AC-02: Отказоустойчивый каскадный транспорт (Failover)
- [x] При включенном `Internet` отправка выполняется через сетевой транспорт (`InternetTransport`).
- [x] При имитации разрыва `Internet = FAIL` транспортный менеджер в течение < 500 мс переключает активный канал на `MockMeshCoreTransport`.
- [x] При экранировании радиоэфира `Mesh = FAIL` пакет складируется в локальную очередь `OfflineQueue` на базе `IndexedDB`.
- [x] При возврате `Internet = OK` очередь автоматически выгружается, а в `AuditLogger` появляется запись о синхронизации пакетов.

### Сценарий AC-03: Сигнал SOS и аварийный канал спасателей
- [x] Кнопка SOS требует подтверждения (удержание 3 секунды для предотвращения случайных нажатий в перчатках).
- [x] Сформированный экстренный сигнал содержит координаты, высоту, процент заряда аккумулятора и цифровую подпись Ed25519.
- [x] Пакеты `EMERGENCY_SOS` автоматически получают наивысший приоритет в очереди и передаются первыми.
- [x] В интерфейсе отображается статус спасательного шлюза с обязательным предупреждением:  
  *«Внимание: отправка выполнена в симулированный шлюз спасательных служб. В реальной чрезвычайной ситуации используйте спутниковый трекер или номер 112»*.

### Сценарий AC-04: Управление профилем, криптографической идентичностью и приватностью
- [x] Экран `ProfilePage` отображает актуальные данные пользователя (имя, email, телефон, биографию, аватар) и fallback-метки.
- [x] Расчет процента заполненности профиля: вычисляется реактивно от 0% до 100% с динамическим прогресс-баром.
- [x] Вкладка «Безопасность» (`security`): отображает сгенерированный открытый ключ Ed25519, отпечаток (fingerprint), кнопку копирования и кнопку ротации ключевой пары с мгновенным обновлением интерфейса.
- [x] Селектор приватности геоданных: позволяет выбрать режим (`NORMAL`, `REDUCED`, `STEALTH`), сохраняя режим локально и на сервере.
- [x] Автоматизированное тестирование: 100% прохождение тестов (`src/views/__tests__/profile-page.test.tsx` — 16 тестов).

### Сценарий AC-05: Геозоны безопасности (`safeRadiusMeters`) и фильтрация координат (FR-002, FR-006)
- [x] При создании и редактировании группы доступна настройка `safeRadiusMeters` (по умолчанию: 500 м).
- [x] На интерактивной карте отрисовывается окружность геозоны безопасности вокруг лидера группы.
- [x] Модуль `LocationFilter` производит вычисление удаления участников по формуле Haversine:
  - До 85% радиуса: статус `INSIDE` (зеленый контур).
  - От 85% до 100%: статус `WARNING` (предупреждение).
  - Свыше 100%: статус `BREACH` (геозона становится красной, выводится плавающий баннер тревоги, пишется событие в `AuditLogger`).
- [x] Фильтрация координат: Deadband отсекает дрожание GNSS до 5 метров; Throttle ограничивает частоту отправки интервалом 5 секунд (до 30 с при разряде аккумулятора $\le 15\%$).
- [x] Сигналы бедствия SOS мгновенно обходят фильтры Deadband и Throttle.

### Сценарий AC-06: Персистентный кэш Cloud Firestore и IndexedDB очереди (Требование 3.1.2)
- [x] Cloud Firestore инициализируется с `persistentLocalCache({ tabManager: persistentMultipleTabManager() })`.
- [x] Очередь `OfflineQueue` использует хранилище IndexedDB `treeline_tracker_db` с поддержкой индексов приоритетов и времени.
- [x] Реализована защита от сбоев в приватных режимах браузера через бесшовный фоллбэк на `localStorage`.

### Сценарий AC-07: Оптимистическая блокировка версий (OCC Engine)
- [x] Все доменные сущности (`Group`, `Route`) содержат поле `version: number`.
- [x] Метод `validateAndIncrementVersion` выбрасывает исключение `ConcurrencyConflictError` при попытке перезаписать сущность с устаревшей версией.
- [x] Успешное сохранение автоматически инкрементирует ревизию (`version + 1`) и фиксирует `updatedAt`.

### Сценарий AC-08: Ролевой доступ RBAC и двухфакторная аутентификация MFA
- [x] Валидация прав ролей `hiker`, `guide`, `rescuer`, `admin` в клиентских компонентах и правилах `firestore.rules`.
- [x] Двухфакторная верификация с 6-значным TOTP-кодом для ролей с привилегированным доступом (`rescuer`, `admin`).
- [x] Интерактивный диалог переключения ролей и симуляции сессий в `ExpeditionStatusBar`.

### Сценарий AC-09: Сквозное E2EE-шифрование группового чата (FR-020, NFR-002)
- [x] При создании группы автоматически генерируется симметричный 256-битный секретный ключ группы в `IdentityManager` (`CryptoService.generateGroupKey()`).
- [x] Сообщения чата передаются с шифрованным объектом `encryptedPayload` (`ciphertext`, `iv`, `authTag`).
- [x] В интерфейсе выводится статус E2EE защиты с бейджем шифрования и отпечатком симметричного ключа группы.
- [x] Поддерживается обратная совместимость при отображении системных уведомлений.

### Сценарий AC-10: Экстренный обход огрубления геоданных (Emergency Bypass, FR-022)
- [x] В случае активации SOS флаг `isEmergency: true` или режим `EMERGENCY` безусловно обходит скрытие координат и фильтры `STEALTH` / `REDUCED`.
- [x] Спасателям и спасательному шлюзу гарантируется передача точных GNSS координат, высоты, скорости и курса без погрешностей.
- [x] Вещание разрешается на всех доступных интерфейсах транспорта (`isBroadcastAllowed('EMERGENCY') === true`).

### Сценарий AC-11: Сетевая защита API-роутов, Rate Limiting и OWASP HTTP-заголовки (FR-026, FR-027)
- [x] Реализован скользящий Rate Limiter по IP-адресу (`api-security.ts`) с лимитом 60 запросов в минуту и отдачей заголовков `X-RateLimit-*` и HTTP 429.
- [x] Все входящие POST/PUT DTO валидируются через строгие Zod-схемы; ошибки валидации возвращаются в унифицированном формате `422 Unprocessable Entity`.
- [x] На уровне `next.config.ts` настроены строгие заголовки OWASP: CSP (OpenStreetMap, Google Gemini, Firebase), HSTS (1 год), X-Frame-Options: DENY, X-Content-Type-Options: nosniff.
