# Функциональные требования (Functional Requirements)

**Статус документа:** `COMPLETED`  
**Категория:** Требования (`02-requirements`)

---

## Реестр функциональных требований

| ID | Категория | Формулировка требования | Приоритет | Текущий статус |
|---|---|---|---|---|
| **FR-001** | Идентификация | Пользователь может создать криптографическую пару ключей (Identity) для своей персоны. | High | `PROTOTYPE` |
| **FR-002** | Группы | Руководитель может создать закрытую группу экспедиции с заданием названия и радиуса безопасности. | High | `IMPLEMENTED` |
| **FR-003** | Группы | Пользователь может присоединиться к группе по коду/приглашению и получить групповой ключ. | High | `PROTOTYPE` |
| **FR-004** | Маршруты | Пользователь может интерактивно нарисовать, сохранить и отредактировать трек маршрута. | High | `IMPLEMENTED` |
| **FR-005** | Маршруты | Система автоматически рассчитывает общую дистанцию, набор/сброс высоты и профиль трека. | Medium | `IMPLEMENTED` |
| **FR-006** | Локация | Система периодически опрашивает источник координат (HTML5 Geolocation / Mock Location). | High | `IMPLEMENTED` |
| **FR-007** | Безопасность | Координаты пользователя упаковываются в структуру `LocationUpdate` и шифруются перед передачей. | Critical | `PROTOTYPE` |
| **FR-008** | Безопасность | Каждый передаваемый пакет подписывается закрытым ключом отправителя (Ed25519) для исключения подделки. | Critical | `PROTOTYPE` |
| **FR-009** | Безопасность | Пакеты защищаются от повторов с помощью `messageId`, `sequence` и временного окна свежести. | Critical | `PROTOTYPE` |
| **FR-010** | Транспорт | `TransportManager` прозрачно выбирает активный канал передачи данных (Internet / Mesh / Queue). | High | `PLANNED` |
| **FR-011** | Транспорт | Система поддерживает работу через `InternetTransport` при наличии сотовой связи. | High | `IMPLEMENTED` |
| **FR-012** | Транспорт | Система поддерживает отправку через симулятор ячеистой сети `MockMeshCoreTransport`. | High | `SIMULATED` |
| **FR-013** | Оффлайн | При отсутствии любого транспорта пакеты помещаются в локальную очередь `Store-and-Forward`. | High | `PLANNED` |
| **FR-014** | Оффлайн | При появлении связи накопленные пакеты автоматически выгружаются и дедуплицируются. | High | `PLANNED` |
| **FR-015** | Экстренные | Пользователь может активировать сигнал бедствия SOS с удержанием кнопки подтверждения. | Critical | `SIMULATED` |
| **FR-016** | Экстренные | Сигнал SOS содержит координаты, метку времени, заряд аккумулятора и подпись. | Critical | `PROTOTYPE` |
| **FR-017** | Экстренные | Симулированный шлюз спасателей `MockEmergencyGateway` регистрирует сигнал SOS. | Medium | `SIMULATED` |
| **FR-018** | ИИ-поиск | Система предоставляет инструмент расчета секторов поиска пропавшего туриста на базе ИИ. | Medium | `PROTOTYPE` |
| **FR-019** | ИИ-поиск | ИИ-выдача содержит уровень достоверности (`confidence`), факторы рельефа и явный отказ от ответственности. | Medium | `PROTOTYPE` |
| **FR-020** | Чат | Участники группы могут обмениваться защищенными текстовыми сообщениями. | Medium | `SIMULATED` |
| **FR-021** | Погода | Система отображает базовый прогноз погоды для контрольных точек маршрута. | Low | `SIMULATED` |
| **FR-022** | Приватность | Пользователь может выбрать режим приватности (`NORMAL`, `REDUCED_PRIVACY`, `STEALTH`). | High | `PLANNED` |
| **FR-023** | Панель статуса | В режиме экспедиции отображается единый статус-бар (GPS, Транспорт, Шифрование, Батарея). | High | `PLANNED` |
| **FR-024** | Симулятор сбоев| Панель разработчика позволяет принудительно эмулировать потерю интернета, радиопомехи и атаки. | High | `PLANNED` |
| **FR-025** | Лог событий | В реальном времени ведется прозрачный аудит-лог событий (`[GPS]`, `[SECURITY]`, `[TRANSPORT]`). | Medium | `PLANNED` |
